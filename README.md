# Forex Signal Research System

A research, backtesting and on-demand signal-analysis system for **real Forex
markets**. **This is a research project, not a profit machine and not an
auto-trader.** Every strategy is treated as an unproven hypothesis until it
survives out-of-sample testing, walk-forward analysis, Monte Carlo stress
testing, and parameter robustness checks. If it doesn't survive that, the
answer is **NO EDGE / NO HAY SEÑAL** and the system will not present a
signal — see [STRATEGIES.md](STRATEGIES.md), [BACKTESTING.md](BACKTESTING.md)
and [SIGNAL_ENGINE.md](SIGNAL_ENGINE.md).

## What this system explicitly does NOT do

- Does not assume any strategy is profitable.
- Does not use martingale or any loss-triggered position-size increase.
- Does not fabricate, interpolate, or "fill in" market data.
- Does not declare a strategy profitable, or show a confidence percentage,
  because a single backtest looked good — every confidence figure shown must
  be backed by sample size, historical win rate and a confidence interval
  (see SIGNAL_ENGINE.md).
- Does not scrape, automate login to, or otherwise interact with Pocket
  Option's platform (there is no official OTC data API — see below for why
  this project analyzes real Forex instead).
- **Does not execute trades, automatically or otherwise, and never touches
  broker funds.** The system's only output is a signal (or "NO HAY SEÑAL")
  that you review and act on manually in your own broker, entirely at your
  own discretion.

## Why real Forex, not Pocket Option OTC

Pocket Option's OTC instruments are synthetic feeds generated by the broker,
with no official public API. Automating anything against that platform —
even just reading data from your own logged-in session — risks account
detection and closure, and this project will not build that. Instead, the
system analyzes **real Forex market data** via a market-data API (Twelve
Data by default — signup only needs an email, no broker account or KYC;
OANDA is also supported for anyone whose broker-account application is
approved — availability varies by country and is out of this project's
control). See [DATA.md](DATA.md) for the full reasoning and its one
important consequence: an edge found on real Forex data is not
automatically valid on Pocket Option's OTC instrument — they are different
data-generating processes.

## Intended workflow (on-demand, manual execution only)

1. You pick a pair (EUR/USD, GBP/USD, USD/JPY, USD/CHF, AUD/USD, USD/CAD,
   NZD/USD, more can be added) and a timeframe (1m, 5m, 15m, ...).
2. You press "BUSCAR SEÑAL". The system fetches real, current market data
   for that pair/timeframe, computes features, and evaluates them against
   whichever strategies have actually passed the validation pipeline in
   BACKTESTING.md.
3. It shows either a signal (pair, direction, entry time, target
   expiry/horizon, a confidence figure grounded in historical sample
   size/win-rate/CI, and the specific conditions that support it) or
   **"NO HAY SEÑAL"** — the system is designed to prefer silence over a
   mediocre signal.
4. **You decide manually** whether to act on it in your own broker. The
   system never places an order.
5. Every signal generated is logged, and later reconciled against its real
   outcome, so the system's actual historical accuracy is measurable instead
   of assumed — see [SIGNAL_ENGINE.md](SIGNAL_ENGINE.md).

## Install

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

## Get real Forex data

**Default: Twelve Data.** Sign up at twelvedata.com (email only, no broker
account or KYC) and grab your API key from their dashboard, then export it —
**never** put it in a file that gets committed:
```bash
export TWELVEDATA_API_KEY="your-key-here"
```
Free tier limits are small (roughly 8 requests/minute, 800/day at the time
of writing — check twelvedata.com/pricing for current values), so fetch
deliberately, not in a tight loop.

**Alternative: OANDA.** If you have (or can get) an approved OANDA practice
account — availability depends on your country and is entirely OANDA's
decision, not something this project can work around — set
`market.data_provider: "oanda"` in `config/config.yaml` and export
`OANDA_API_TOKEN` instead.

## Initialize the database

```bash
python scripts/init_db.py
```

This creates `data/otc_research.db` (SQLite) with the schema described in
[DATA.md](DATA.md). It never drops or alters existing tables.

## Fetch real candles from the configured provider

```bash
# most recent 500 closed 1-minute candles
python scripts/fetch_market_data.py --pair EUR_USD --timeframe 1m --count 500

# a specific historical window, for backtesting
python scripts/fetch_market_data.py --pair EUR_USD --timeframe 5m \
    --start 2026-01-01T00:00:00Z --end 2026-01-08T00:00:00Z
```

Only fully closed candles are ever stored — the still-forming current
candle is always discarded. See [DATA.md](DATA.md) for the validation rules
applied (duplicate/out-of-order timestamps, gaps, impossible OHLC values,
suspicious moves, source changes — nothing is ever fabricated to fill a
gap).

## Import a CSV file instead

```bash
python scripts/import_csv.py --asset EUR_USD --timeframe 1m \
    --csv data/raw/eur_usd_1m.csv
```

pip install -e ".[dev]"
